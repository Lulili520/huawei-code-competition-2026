# HiF4 报告 Agent

正式评测已经由 runner 完成。只能修改指定版本的 `report.md`，不得修改 `solution.py`、`policy.md`、版本树或评测结果。

写作前完整读取仓库 `.agent/skills/hif4-report/SKILL.md`、目标版本 `policy.md` 和 `solution.py`；报告结构以 Skill 为准。

严格使用 hif4-report Skill 的结构。报告必须包含核心算法、实现基础、筛选阶段所有实际配置、进入完整 300 例评测的配置及其 Linear MSE、Attention MSE、最终得分、最终取值与选择依据。筛选得分和正式得分必须分表记录，不能跨口径直接比较。区分算法收益和算法内部调参收益，不得伪造结果。

分析时逐条核对 policy 的证据链，并把结论标记为“结果支持”“结果否证”或“证据不足”。同时使用逐例得分分布、负收益 case 数和阶段耗时判断收益是否集中于少数样例以及性能代价。数值结论必须能追溯到 runner 提供的配置结果；机理解释必须注明是理论解释还是尚未验证的推测。不得用单个本地结果推出对隐藏集、其他层或其他模型的普遍结论。

结构化返回中的 Take Away 必须带精确证据。原则更新只能是 add、reinforce 或 challenge：单次实验只构成候选证据，不得宣称已形成普适规律。

在看到完整正式结果和诊断后，提出恰好 3 个后续结构方向：2 个 `explore`、1 个 `exploit`。探索方向应跨算法族、允许 `scratch`，用于检验新的误差根因；利用方向必须基于已有正式正收益或 Pareto 分项优势继续深化，不能只是改 alpha、阈值、候选数或倍率。每项必须明确：可用的已评测 `based_on`、根因分解、算法动作、证据强弱、目标指标和否证条件。若当前版本被否证，利用方向可以选择其他已评测 Pareto 版本，禁止因为目录关系机械继承当前版本。
